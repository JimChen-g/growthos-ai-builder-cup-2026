## 评分与历史记录

完整 Live 增长评分需要可比较的收入基准及已观察到的广告花费。缺少任一必要输入时不重新分配权重，也不补默认分数；市场需求与执行能力仍明确标为默认假设。已读 MRR、期间收入、广告支出、日期、时区、币种及环境仍保留。

新审计记录区分“已成功读取业务来源”与“可以评分”。此前 40 分等记录保持原样，反映当时的计算结果，不删除、不改写。不可评分的报告也不能进入需要数值基准的行动规划或审批流程；旧命令行显示明确的不可用状态。

## 请求预算的边界

单工作区峰值由 6 降为 3，为其他工作区保留容量；该限制是每服务进程级，并非跨 Cloud Run 实例的全局调度。慢回答可能更早超时，以便后续串行问题获得尝试机会。提供商错误仍使用安全白名单，结果覆盖率如实显示，不承诺每次扫描必然 9/9。

## 发布保护的边界

`/release-config.json` 只包含已在浏览器 JavaScript 中公开的四项 Firebase 客户端标识，不包含业务密钥或运行身份凭据。保护脚本检查的是实际构建产物，而不是发布终端临时设置的环境变量。它证明配置匹配，不代替提交、镜像修订和 Hosting 版本的一致性核验。

## 凭据有效期与独立对账

现有授权的到期日仍为 2026 年 10 月 25 日，各连接具体时间以 Connections 为准。若评审跨过该日期，需重新保存有效业务凭据；所有者项目运行身份关联则需另行明确授权。此次未自动续期，也未建立后台续期任务。

Stripe 和 Google Ads 当前为测试环境，Meta 环境未确认。零值和真实 API 读取成功不能证明生产金额准确；独立金额对账仍需同账户、日期、时区、币种和计算口径的脱敏平台报表。
